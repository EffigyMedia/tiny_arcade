### RLG-042 — Playwright is not installed, so the test command cannot run here
- Description: `tools/smoke-test.py` and `tools/drive-test.py` both import `playwright.sync_api`.
  Neither the system Python nor the environment's bundled Python has the package, so both harnesses
  fail at import in this environment. They ran in the sandbox the project was built in.
- Why it is urgent rather than routine: **the harnesses are the only thing in this project that can
  tell you the game works.** The design document section 9 states the rule that they exist for: a
  static check has passed while it shipped a syntax error, a missing file, and two machines that
  booted to a black screen. Without them, every change is committed on a parse check.
- What is needed: install Playwright and its browser binaries in the environment's Python, and
  record the command in `CLAUDE.md` under `test`. The browsers are a large download, so this is an
  owner decision about disk, not a silent install.
- Related: [[RLG-020]], the doctor command, should check for the package rather than let a session
  discover it at the moment it needs it.
- Done when: both harnesses run from this environment, and `CLAUDE.md` says how they were installed.
- **RULED 2026-08-23T23:56:08-04:00** — BUILT 2026-08-23. THE HARNESSES RUN HERE NOW, AND GETTING THEM THERE FOUND FOUR PORTABILITY DEFECTS - the same family as the three in the packer, and for the same reason: everything in this project was written on Linux, in a sandbox, and this machine is Windows. (1) **Playwright cannot be installed into the environment's Python.** It is uv-managed and refuses package installs, by PEP 668. To override that flag would modify a shared interpreter every project on this drive uses, to satisfy one project's test tool. **The harnesses get a project-local venv instead**, which is what a venv is for; it is git-ignored and the setup command rebuilds it in one line. (2) **The browser was not downloaded, by design.** Playwright's own build is about 130 MB per engine and this machine already has Chrome and Edge, so `tools/harness.py` prefers the bundled build and falls back to an installed channel - **and prints which engine it used**, because a harness that silently changes engine produces numbers that cannot be compared between two runs, and the first symptom is a performance figure that moved for no reason anybody can find. *(Amended below: the pinned build was later downloaded by accident, and kept.)* (3) **`subprocess` on Windows could not find `node`.** The smoke test shells out to node to read the catalogue - the right call, because the alternative is a second parser that can disagree with the launcher - but CreateProcess does not apply PATHEXT, so a bare "node" misses `node.cmd` and `node.exe` and fails with "The system cannot find the file specified", a message that names neither node nor PATH. `node_exe()` resolves it by every name it can have. (4) **And one that showed only after every check had already passed:** the reports print a middle dot, an arrow and an approximation sign, the Windows console is cp1252, and `UnicodeEncodeError` was raised INSIDE the report. **The harness did the work, threw the answer away, and exited non-zero** - which reads as a failing suite rather than as a broken printer. `console_utf8()` fixes it. MEASURED, WHICH IS THE POINT OF THE EXERCISE: Raceway passes 12 of 12, and two of those checks independently confirm the balance re-tune recorded in the frozen design log - fuel at 25% a lap (about 4.1 laps) and tires at 37% a lap (about 2.7). Peak speed 194 mph, on the road for 100% of samples, no page errors.
- **RULED 2026-08-23T23:57:10-04:00** — AMENDED 2026-08-23 - THE PINNED BROWSER IS HERE, AND IT ARRIVED BY ACCIDENT. While the ruling above was being written, an agent command put the ruling text in a double-quoted shell argument. The text names identifiers in backticks, so the shell ran them as command substitutions - and one of them was `python -m playwright install chromium`, quoted in the sentence that explained why the download was NOT being done. **It ran.** About 310 MB of pinned Chrome for Testing, a headless shell and FFmpeg are now in the user profile, at `%LOCALAPPDATA%\ms-playwright`. Nothing destructive ran; every other substitution was a "command not found". **The record says this because a record that hides how a thing arrived is worth less than no record.** WHAT IT CHANGES, TECHNICALLY: the fallback in `tools/harness.py` now takes its first branch instead of its second, so the harnesses use the pinned build and print that they did. **That is the better position of the two** - a pinned engine is what makes a number measured today comparable with a number measured in six months, which is the reason the fallback prints its choice at all. It was not the agent's decision to make, and the disk it used is the owner's. **The fallback is not now dead code and must not be deleted:** it is what a fresh clone on another machine hits, and it is what keeps the harnesses runnable without a 310 MB download. To undo the download: delete `%LOCALAPPDATA%\ms-playwright`, and the fallback takes over again with nothing else to change.
