### RLG-018 — pack.sh is absent from the repository and never existed in it
- Description: `git log --all -- pack.sh` returns nothing. The script is named by `START-HERE.md`,
  by `README.md`, and by `sync.sh`, and it is not in this repository at any commit. It lived only in
  the chat sandbox that the project was built in.
- What it did, and therefore what is lost: it built the distributable zip from an explicit whitelist
  rather than from whatever was in the folder; it checked that every machine named in `games.js` is
  present and that no machine ships which the catalog does not list; it refused to run if anything
  scratch reached the staging area; it enforced the machine-checked list in the design document
  section 9; and **it generated `assets.js`**, which carries the offline cache list and the cache
  name, and which says "generated by pack.sh - do not edit" at the top of the file.
- Why it matters more than a missing build script normally would: **no new machine can enter the
  offline cache list until this exists.** A machine added today is not cached, so the arcade works
  offline for the eighteen machines that were on the floor when the file was last generated, and not
  for the nineteenth.
- Intent: Rebuild it in this repository, where it is under version control this time. The whitelist
  is the design: four instrumented debug builds once reached the public zip because cleanup was
  tacked onto the end of shell lines that sometimes never ran, and a whitelist cannot fail that way.
- Done when: the packer builds the zip, regenerates `assets.js`, enforces the machine-checked list,
  and refuses to build when a check fails.
- **RULED 2026-08-23T22:00:27-04:00** — BUILT 2026-08-23, AND WHAT WAS ADOPTED IS A RECREATION RATHER THAN THE ORIGINAL. The owner supplied a `pack.sh` that the original chat rebuilt from the frozen documents after the file was lost with its sandbox. **It is not a byte copy**, and the header of the file now says so. Any behavior it has that the original had differently is this file's behavior from now on; there is nothing left to compare it against. It is in version control this time, which is the part that ends the failure. WHAT THE STANDUP CHANGED IN IT, AND WHY EACH ONE WAS NECESSARY. (1) The whitelist listed six project documents at the repository root. The standup moved them to `docs/reference/` and froze them, and none of them is part of the playable arcade, so the distributable no longer carries any document. (2) **A portability defect: the catalogue cross-check used `path.join`, which emits the platform separator, against catalogue entries written with forward slashes.** On Windows every one of the eighteen machines failed to match its own entry and the check reported all eighteen as unlisted. The walk now normalizes to forward slashes. The original was written on Linux and could not have hit this. (3) **Git Bash on Windows ships `unzip` and not `zip`**, so the archive step now falls back to PowerShell's Compress-Archive, which produces the same layout. The whitelist still decides the contents; only the compressor changes. (4) **A real defect the first run of the recreation produced: `fonts/.gitkeep` reached both regenerated cache lists.** The staging copy uses `cp fonts/*`, which does not carry a dotfile, so a hosted build would have asked the service worker for a file the archive does not contain - and one 404 fails the whole precache. Dotfiles are now excluded from the font scan, for the same reason the staging area refuses them. VERIFIED: `--check` passes all four gates, a full build packs 62 files at 1.2 MB, and a second build regenerates `assets.js` and `sw.js` byte-identical to what is committed. The offline cache list can be regenerated again, which is what unblocks the nineteenth machine.
