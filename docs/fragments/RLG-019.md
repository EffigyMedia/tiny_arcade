### RLG-019 — Retire or rewrite sync.sh: the working folder is now the repository
- Description: `sync.sh` clones the remote to a temporary folder, copies a named list of files over
  the top, and commits what differs. It exists because the working folder was not a repository - the
  project was built in a chat sandbox and pushed its output to GitHub.
- What changed: the working folder **is** this repository. A clone-and-copy push is now a way to
  lose work, because it copies a subset of the folder and it knows nothing about the history it is
  writing into.
- The one part worth keeping: the guard that refuses to push a build whose catalog points at files
  missing from the staging area. Dead links were the site's chronic 404, and that guard is what
  ended it. It belongs in the packer ([[RLG-018]]) or in a deploy step, not in a copy script.
- Intent: Decide between two ends - delete it, or rewrite it as a GitHub Pages deploy step that
  works from this repository. Either way the file must stop to describe a workflow that no longer
  exists.
- Note: the standup already removed two names from its copy list, because the script runs under
  `set -e` and a missing name stops the push part way through. That was a repair to keep it from
  breakage, not an endorsement of it.
