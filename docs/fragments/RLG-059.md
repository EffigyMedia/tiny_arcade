### RLG-059 — Restore the six fixes that the web-UI uploads reverted
- **RULED 2026-08-28T08:42:30-04:00** — - **What happened.** Six commits reached `origin/main` from the Claude Chat session that governed
  this project before the standup, each one titled "Add files via upload". A GitHub web-UI upload
  replaces a whole file. The chat was holding copies taken before v0.9.5, so every file it uploaded
  carried the pre-audit content, and six shipped fixes went back out of the product under a commit
  message that says nothing was removed.

- **This is the failure mode to remember, and it is not carelessness.** A whole-file upload has no
  merge step and therefore no conflict. Git cannot warn about it, because from Git's side the upload
  is a legitimate new version of the file. **The only signal is a diff nobody is required to read.**
  The reverted work stayed reverted through a green `pack.sh --check`, because a static gate has no
  memory of what a file used to contain.

- **What was reverted, and what is restored.**

  | File | What went missing |
  |---|---|
  | `arcade.js` | `A.version`, the whole `A.menu` cursor, the pad-subscriber swallow, the `.ark-cursor` outline |
  | `index.html` | the dead rack-level launch handler came back; the space key stopped being claimed |
  | `tools/smoke-test.py` | the launcher check, and the `harness.py` import that makes it run on Windows |
  | `tools/drive-test.py` | the same `harness.py` import |
  | `pack.sh` | the Windows path-separator fix, the dotfile exclusion in the cache list, `LICENSE` and `404.html` in the archive |

- **Each one was re-verified against the file as it stands now, not assumed.** The dead rack handler
  is the case that mattered: it is only dead because a cabinet is a `<div>` with `data-href`. Had
  the chat turned cabinets back into anchors, deleting the handler would have broken every launch.
  It did not - `index.html` still builds a `div.cab` with its own click handler - so
  `cab.getAttribute('href')` still returns null and the deletion is still correct.

- **The tombstone in `index.html` was corrected while it was reinstated.** The original text asserted
  that this handler was the 404 the owner's friends reported. That claim was withdrawn when it was
  measured, and the replacement says so plainly rather than reprinting a disproved cause.

- **Nothing the chat built was rolled back.** Privateer, `CFG.overlay` in the engine, the
  `pointer-events` fix on Highway's warning banner, and the new "every `.md` is accounted for" gate
  in `pack.sh` are all kept. `pack.sh` was repaired hunk by hunk rather than checked out whole,
  precisely so that gate survived. `CLAUDE.md` is declared in `NOT_SHIPPED`, because it describes how
  the product is built and is not part of it.

- **Proof.** `./pack.sh --check` passes all six gates. `smoke-test.py` and `drive-test.py` were run
  after the restoration and their results are recorded in this unit's commit.

- **The workflow rule this earns.** The chat is no longer the place the product is edited - the owner
  has said the environment is ready and the work moves here. If a file is ever uploaded through the
  web UI again, **read the diff against the last known-good commit before doing anything else.** A
  green build is not evidence that nothing was lost.
