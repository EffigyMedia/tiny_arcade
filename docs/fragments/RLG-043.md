### RLG-043 — Hosting: stay on GitHub Pages, or move to Cloudflare Pages
- Description: The arcade is served by GitHub Pages from this repository. The owner is considering
  Cloudflare Pages instead. **Deferred on 2026-08-23, not declined** - the owner chose to return to
  development first. This item holds what was established, so the decision does not have to be
  reasoned out a second time.
- **The fact that forces the question: on GitHub Free, a private repository loses its Pages site.**
  Pages on a private repository needs a paid plan. So the repository is public because the hosting
  is free, not because publishing the source was chosen. Cloudflare Pages builds from a private
  repository at no cost, which separates those two decisions for the first time.
- **What a private repository would and would not buy.** It hides the commit history, the comments,
  the unshipped work in branches, and the Firebase rules files. **It does not hide the app** - the
  client JavaScript is served to every visitor whatever the repository says. And it is not
  retroactive: forks stay public and split into their own network, clones and caches keep
  everything, so **a credential ever committed must be rotated rather than hidden.**
- What Cloudflare improves, beyond the private-repository question:
  - **Root-path serving.** A GitHub Pages project site lives at `user.github.io/<repo>/`; Cloudflare
    serves at the root of a `pages.dev` project. That removes a class of base-path and service
    worker scope problems. This project has already been bitten once by a path that was derived one
    level short.
  - `_headers` and `_redirects` files, so cache-control is a real setting rather than whatever the
    host does. GitHub Pages cannot do this.
  - Per-branch preview deployments.
- The limits, as read on 2026-08-23 and **worth re-checking, because they move**: 500 builds a
  month, one concurrent build, 20 minutes per build, 20,000 files per deployment, 25 MiB per file,
  unlimited bandwidth for static assets. This build ships 62 files at 1.2 MB, so none of them is
  close.
- The costs that are real rather than table-shaped: a custom domain normally needs its DNS on
  Cloudflare, which makes one company the DNS, the CDN, and the host; the Cloudflare GitHub App
  needs read access to the repository; and the free-plan terms restrict content that is
  disproportionately not HTML, which an arcade of HTML, JavaScript and fonts is not.
- **One migration cost that is not reversible for the people it affects:** a player who installed
  the arcade from the `github.io` origin stays pointed at it. A different origin is a different
  install and a different `localStorage`, so saved scores do not follow.
- The owner's stated constraint is that no service is paid for. **Both options satisfy it.**
- Suggested shape, if this is taken up: move this project first as the pilot and keep it public.
  The whole flow gets learned on the app that was just cleaned up, with nothing at risk, and the
  repository stays the source of truth either way - so a move back is a DNS change.
- Done when: the owner rules, and the answer is recorded in the design document's Decision Log.
