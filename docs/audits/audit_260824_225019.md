# Audit Report — 2026-08-24 22:50:19

Project version audited: v0.9.4 (`57a5543`, clean tree)
Scope: **each game (all 18 cabinets) and the arcade launcher**, plus the shell surface they consume
(`arcade.js`, `audio.js`) and the driving games' seam usage of `road.js`.
**Excluded:** the internals of `road.js` (9,849 lines — covered only through its two callers, the
drive harness, and the frozen `REFACTOR.md`), `sw.js` cache internals (read, not walked),
`pack.sh`, the fonts pipeline, and the process documents.
Prior audit: first audit.

## Executive Summary

The arcade is in **good health where machines can check it, and worse where they cannot**. Every
build gate passes, all 18 cabinets boot with paint on the canvas and a clean console, and both
driving games pass 21 of 21 harness checks. The games' internal logic is generally well built —
Penboy, Soviet Blocks, and Popshot are exemplary — and the shell contract is honored everywhere:
no cabinet defines `--stage-h` or `--safe-top` in its `:root`.

The findings that matter live in the gaps no harness covers:

1. **AUD-001 (Critical, proven live): tapping any cabinet in the launcher races two click
   handlers, and the loser navigates to `/null`.** A dead handler from an older anchor-based
   launcher still fires on every tap, reads an attribute that no longer exists, and 80 ms after the
   real navigation overwrites it with `location.href = null`. On a warm cache the real navigation
   wins; on a first visit over a network it loses. **This is almost certainly the 404 the owner's
   friends reported** — they had the right URL, opened the arcade, tapped a game, and got a 404.
   It was reproduced on the live site during this audit. The fix is deleting one dead handler.
2. **AUD-002 / AUD-003 (High): two cabinets break the "no input mode is second-class" promise.**
   Aegis cannot be played at all with a keyboard or a gamepad. Vector's gamepad can fire but can
   never turn or thrust.
3. **AUD-004 (High): Phalanx's title screen draws the generic pixel space-invader** — the exact
   icon the clone posture forbids — while the game itself uses its own original creatures. It is
   the one image in the repository a rights holder could screenshot, and it sits on the front door.
4. **AUD-014 (Medium): no test exercises the path the Critical bug lives on.** Both harnesses
   `goto` a cabinet's URL directly; nothing ever clicks a cabinet card, and nothing plays a cabinet
   through each input mode. The three worst findings in this report were all invisible to green
   runs.

Counts: **1 Critical · 3 High · 8 Medium · 4 Low**, plus 4 unconfirmed potentials.

Before anything else ships: fix AUD-001 (small, and it is the live-site failure), then AUD-002/003.

## Critical Issues

<a id="aud-001"></a>
### AUD-001 — Every cabinet tap races a dead click handler that navigates to `/null`
- Severity: Critical
- Area: A. Correctness (Must-flow F2) / B. Duplicate implementations
- Evidence: `index.html:734-742` — each `.cab` div gets its own click listener that plays
  `UI.launch()` and navigates to `dataset.href` after **130 ms**. `index.html:1048-1060` — a
  second, older listener on `#rack` ("coin-op launch") also fires on the same bubbled click, plays
  a second coin jingle, and after **210 ms** runs `location.href = cab.getAttribute('href')`. Cabs
  are `<div>`s: `getAttribute('href')` is **null** (verified on the live site), and
  `location.href = null` navigates to `<base>/null`. Reproduced live: the exact two assignments at
  the exact offsets, against a cache-bypassed cabinet URL, landed the page on
  `https://effigymedia.github.io/tiny_arcade/null`.
- Impact: any visitor whose cabinet navigation has not committed within ~80 ms of starting — that
  is, **every first-time visitor over a real network** — gets a 404 instead of a game. Until
  v0.9.4's `404.html`, that was GitHub's own error page. The developer never sees it, because a
  warm service worker commits the navigation in milliseconds. Secondary: two overlapping launch
  jingles on every tap, for everyone, always. **This matches and most plausibly explains the
  owner's field report of friends getting 404s with the correct URL.**
- Recommendation: delete the rack-level handler (`index.html:1047-1060`) entirely — the per-cab
  handler already does the job. Grep for other survivors of the anchor-era launcher while there.
- Effort: S
- Status: Open

## High Priority Issues

<a id="aud-002"></a>
### AUD-002 — Aegis cannot be played with a keyboard or a gamepad
- Severity: High
- Area: A. Requirement compliance (success criterion 2; definition of done)
- Evidence: `games/ge/aegis.html:755-767` — the only in-play input is `pointerdown` on the canvas.
  The keyboard handler and the pad handler both service menus only; there is no crosshair, no
  cursor, and no fire action for either.
- Impact: a keyboard-only desktop player or a gamepad player can open the game and never fire a
  shot. The design document's "no input mode is second-class" is a Must.
- Recommendation: a movable crosshair (arrows / left stick) plus fire (space / A) is the standard
  Missile Command port answer. The packer's static checks cannot catch this class; see AUD-014.
- Effort: M
- Status: Open

<a id="aud-003"></a>
### AUD-003 — Vector's gamepad can fire and hyperspace but never turn or thrust
- Severity: High
- Area: A. Requirement compliance (success criterion 2)
- Evidence: `games/ge/vector.html:710-726` — the 16 ms poll reads only the keyboard `keys` map;
  `pad.onPress` maps `a`→fire and `b`→hyperspace and nothing else. No `pad.down('left')` /
  `axis()` path exists (compare Feather `:598-603`, which does it correctly).
- Impact: on a gamepad the ship drifts in a straight line until it dies. Fire-only.
- Recommendation: extend the existing 16 ms poll with `AR.pad.down('left'/'right'/'up')` or
  `AR.pad.axis()`, exactly as Feather and Deep already do.
- Effort: S
- Status: Open

<a id="aud-004"></a>
### AUD-004 — Phalanx's title art draws the generic pixel space-invader, not the game's creatures
- Severity: High
- Area: E. Privacy & licensing (clone posture) / F. Experience
- Evidence: `games/ge/phalanx.html:555-583` — the title renders an 8×4 rank of pixel invaders with
  the two-frame alternating-leg walk and antennae: the iconic invader silhouette. The in-game
  enemies (`:378-406`) are the original medusa/crab/louse x-ray designs and share nothing with it.
- Impact: the design document's clone posture is a **hard constraint**: "no lifted sprite shapes…
  where a mechanic needs a familiar read, express it in our own visual language." The game does;
  the title reverts. It also contradicts the LICENSE's claim that "no sprite… of any other party
  is reproduced," and it advertises art the cabinet does not contain — the same failure class as a
  stale attract card, pointed the wrong way. Honest caveat: this is not asserted to be a
  byte-for-byte copy of Taito's bitmap; it is the unmistakable invader icon rather than this
  game's own designs, and on the shelf carrying the project's stated legal exposure that is the
  distinction that matters.
- Recommendation: redraw the title rank using the game's own three body plans (the drawing code
  already exists in `creature()`); keep the composition, which is good.
- Effort: M
- Status: Open

## Medium Priority Issues

<a id="aud-005"></a>
### AUD-005 — Difficulty halves on 120 Hz screens in Swarm and Aegis (dt² probabilities)
- Severity: Medium
- Area: A. Correctness / D. Performance portability
- Evidence: `games/ge/swarm.html:217` (`Math.random() < 0.014*k*60*dt*10`),
  `games/ge/aegis.html:172,176`. With `k = dt*60`, the per-frame probability is proportional to
  **dt²**, so the per-second event rate is proportional to frame rate. Measured algebraically: at
  120 Hz, Swarm's dive-bombing and Aegis's spawn pressure run at ~half their 60 Hz rates.
- Impact: high-refresh phones — now common — play a noticeably easier game. Scores are not
  comparable across devices.
- Recommendation: make the probability linear in dt (`1 - Math.exp(-rate*dt)` or an accumulator),
  or adopt Penboy's fixed 120 Hz timestep (`penboy.html:1230`), which is the house-best pattern.
- Effort: S
- Status: Open

<a id="aud-006"></a>
### AUD-006 — Ribbit: pads sink on the wall clock, so pausing can kill you
- Severity: Medium
- Area: C. Edge cases (pause fairness)
- Evidence: `games/ge/ribbit.html:196-200` — `sunk()` phases off `performance.now()`, which keeps
  running while the shell has the game paused; `:277` drowns you the frame a ridden pad reads as
  sunk. Pause 2–3 s while riding a pad and resume into an instant death.
- Impact: the pause menu — a shell feature every cabinet promises — is unsafe in exactly one game,
  and the death is unattributable from the player's side.
- Recommendation: drive pad phase from accumulated game `dt` instead of wall time.
- Effort: S
- Status: Open

<a id="aud-007"></a>
### AUD-007 — Burrow: the fire-breathing drake is fully built and can never spawn
- Severity: Medium
- Area: B. Dead code / A. Missing features
- Evidence: `games/ge/burrow.html:160` — `kind: i%3===2 ? 'wisp' : 'grub'`. The drake's complete
  system — telegraph, three-cell flame with kill check (`:308-329`), its own art (`:705`), breath

- Impact: the game ships with two enemy behaviors instead of three; the Dig Dug archetype this

- Recommendation: spawn drakes from some level (for example `i%3===2 ? 'wisp' : i%4===3 ? 'drake'
  : 'grub'` gated on `level >= 3`), then rebalance; or delete the system deliberately.
- Effort: S (enable) — the balance pass is the real work
- Status: Open

<a id="aud-008"></a>
### AUD-008 — Coil: the turn buffer's two branches are identical, so a fast double-turn eats the first swipe
- Severity: Medium
- Area: A. Functional correctness
- Evidence: `games/ge/coil.html:164-168` — `if(!queued) queued = {c,r}; else queued = {c,r};`. The
  comment above it, and the CONTROLS screen (`:417`), both promise "one turn is buffered so a
  quick double round a corner lands." As written the second input **replaces** the queued first,
  so of a fast double exactly one lands — the documented behavior's opposite.
- Impact: the fast-corner move the game itself teaches fails at the moment it matters (tick
  interval shrinks to 58 ms at length).
- Recommendation: a real two-slot buffer: if a turn is queued, hold the second until the first is
  consumed.
- Effort: S
- Status: Open

<a id="aud-009"></a>
### AUD-009 — Canvas-bound touch leaves dead zones the interaction principle forbids
- Severity: Medium
- Area: F. User experience / A. Design alignment
- Evidence: 13 of 16 non-driving cabinets bind touch to the canvas, not the page (only Penboy,
  Deep, Derelict use `Arcade.gesture`; the frozen `DESIGN.md` §2 claims "built, and every machine
  uses it," which is false). Where the canvas aspect is much squarer than a phone the dead zones
  are large: **Coil** (306×378 logical — roughly 150 px dead bands top and bottom on a 390×844
  phone) and **Feather**, whose *thrust* zone is the bottom strip **of the canvas** while the
  natural thumb position is the bottom of the screen — off-canvas, doing nothing. Popshot,
  Ricochet, Ribbit, Blocks are near-full-height and effectively fine.
- Impact: the exact "fight with the game rather than its hazards" the design document's
  interaction principle names. Worst in Feather, where thrust timing is the game.
- Recommendation: route swipe/drag through `Arcade.gesture` (Coil, Ziggurat, Ribbit are one-liner
  conversions), or extend hit areas to `#stage`. Feather's thrust strip should be a screen-bottom
  zone, not a canvas-bottom zone.
- Effort: M across the set
- Status: Open

### AUD-010 — Soviet Blocks implements Tetris-Guideline signature features, sharpening the stated top clone risk
- Severity: Medium
- Area: E. Licensing (risk posture, not a code defect)
- Evidence: `games/ge/blocks.html` — ghost piece (`:404-408`), hold with one-per-piece rule

- Recommendation: an owner decision, not a code fix: either accept under the free-shelf posture

- Status: Open

<a id="aud-011"></a>
### AUD-011 — Keyboard and gamepad can only ever press the first button on any game menu
- Severity: Medium
- Area: F. User experience / A. Requirement compliance (partial)
- Evidence: every non-driving cabinet's veil handler is the same pattern — Enter/space (or pad A)
  clicks `veilBody.querySelector('.btn')`, the **first** button (for example
  `coil.html:451-464`). There is no focus movement. PLAY and PLAY AGAIN are always first, so the
  play loop works; OPTIONS, CONTROLS, and QUIT are mouse/touch-only.
- Impact: a keyboard or pad player cannot read any CONTROLS page — the page that exists to tell
  them their controls — or quit to the arcade without the mouse. (The shell's own pause menu *is*
  pad-navigable, which sets the standard the game menus miss.)
- Recommendation: a shared arrow/dpad focus cycle in the veil pattern; it is one function copied
  eighteen times either way, or a candidate for the shell.
- Effort: M
- Status: Open

<a id="aud-014"></a>
### AUD-014 — No test exercises launcher navigation or per-input playability
- Severity: Medium
- Area: H. Test coverage
- Evidence: `tools/smoke-test.py:117-134` and `tools/drive-test.py` both navigate straight to a
  cabinet URL with `page.goto`. Nothing clicks a cabinet card (AUD-001's path), nothing sends
  keyboard input to a cabinet in play (AUD-002/003's class), and nothing pauses and resumes
  (AUD-006's class).
- Impact: the Critical and both High findings of this audit sat behind 18/18 and 21/21 green runs.

  (2) after boot, press PLAY via Enter and assert the veil hides (catches menu-input regressions);
  (3) optionally send arrows for 2 s and assert a game-state variable moved (catches AUD-002/003).
- Effort: S–M
- Status: Open

## Technical Debt

- **The veil/menu system is copied eighteen times** (`openVeil`, `showTitle`, `showOptions`,
  `showControls`, `fitTight` — near-identical in every GE cabinet). Tax: AUD-011 must be fixed 18
  times; any menu improvement costs 18 edits. The design's own backlog rule ("consolidate on the
  third repeat") tripped long ago. Candidate for a shell veil helper — with the film-grade lesson
  in mind: mechanism only, no opinions.
- **Input handling is per-cabinet artisanal.** The same audit that found AUD-002/003 found five
  different pad-polling idioms. A tiny shared "held-directions" helper would have prevented both
  High findings structurally.
- **Frame-stepping idioms vary** from fixed-timestep (Penboy) through `k = dt*60` scaling to raw
  dt² probabilities (AUD-005). One documented house pattern would end the class.
